TESTAROSSA OS - TEST AND DEBUG GUIDE FOR CLASSMATES
====================================================

Testarossa now boots into a graphical desktop. The text shell still exists
(for the exam demo and for the shell tests) and is started with one command.
Your job is to check what is built, break it on purpose, and report what
you find. You do not need to read the code to do most of this.

WHAT IS NEW (read this first if you tested before)
--------------------------------------------------
  - Terminal window: press  t  (or click "Terminal (T)") to run the shell
    inside the desktop.
  - Several windows: up to four at once. Tab brings the bottom one to the
    top, Esc closes the top one.
  - Mouse: click tiles, rail squares, Archive rows, the x close box, and the
    dock buttons.
  - The boot log has a new line: "mouse: PS/2 mouse on, IRQ12".
  If you already did Parts A-F, pull the latest code (git pull), rebuild
  (make clean && make), redo Test 2 and Test 3, then do PART B2.

FOLLOW-UP: WHAT WE NEED FROM YOU
--------------------------------
  1. Run PART B2 (Tests 25-29) and report PASS or FAIL for each.
  2. D1 now also applies to the Terminal window. Try it there and report.
  3. D7 long run: leave the desktop running 10 minutes WITH the Terminal
     and two other windows open, moving the mouse now and then.
  4. Mouse edge cases: move the pointer fast into every corner, click and
     hold, click with the right button. Report anything odd (pointer
     jumping, stuck buttons, clicks that open the wrong thing).
  5. Want to write code? The next open feature is dragging windows by their
     title bar (docs/FUNCTIONS.md, section 8). Ask the project owner first,
     and use a branch named feature/<short-name>.

Work in this order:

  PART A  Must do first (about 20 min)   Tests 1-3
  PART B  Desktop checks (about 30 min)  Tests 4-11
  PART B2 Terminal, windows, mouse (about 20 min) Tests 25-29
  PART C  Text shell checks (about 20 min) Tests 12-19
  PART D  Kernel self-tests in the log   Tests 20-22
  PART E  Crash tests (about 10 min)     Tests 23-24
  PART F  Debug challenges (rest of time) Challenges D1-D7

Each test has an EXPECTED result. If what you see differs, write it down
(see HOW TO REPORT at the bottom). A difference is a bug, even a small one.


0. WHAT YOU NEED
----------------
- Windows 10 or 11 with WSL2 and Ubuntu installed.
  (If you do not have it, open PowerShell as administrator and run:
   wsl --install -d Ubuntu  then restart the computer.)
- The project folder (git clone, or the folder you were given).

Setup, once, inside the Ubuntu app:

    sudo apt update
    sudo apt install -y nasm qemu-system-x86 make gcc

Go to the project. Windows drives appear under /mnt:

    cd /mnt/c/path/to/Operating_System

Check the tools (each should print a path):

    which nasm qemu-system-i386 make gcc


=====================================================================
PART A - MUST DO FIRST
=====================================================================

TEST 1 - CLEAN BUILD
--------------------
    make clean
    make

EXPECTED: no line that starts with "error". The file build/testarossa.elf exists.
A warning "LOAD segment with RWX permissions" is known and OK.


TEST 2 - BOOT LOG
-----------------
    make run

A QEMU window opens. The terminal prints these lines, in this order:

    Testarossa OS v0.1.0 booting...
    GDT loaded
    IDT loaded
    PIC remapped to vectors 32-47; IRQ0 (timer), IRQ1 (keyboard), IRQ12 (mouse) unmasked
    mouse: PS/2 mouse on, IRQ12
    PIT programmed to 100 Hz
    PMM: memory map read, NNNNNN KiB free
    PMM self-test: PASS (...)
    Paging on: first 1 GiB identity-mapped with 4 MiB pages
    paging self-test: PASS (...)
    heap self-test: PASS (...)
    framebuffer: PCI slot 2, memory at 0x..., 800x600x32, pitch 3200

EXPECTED: all lines appear, and every "self-test" says PASS.
If a line says FAIL, that is the most important bug to report.

Close the QEMU window when done.


TEST 3 - THE DESKTOP APPEARS
----------------------------
    make run

Look at the QEMU window (it should now show the desktop, not text).

EXPECTED:
  - A dark navy screen with a few faint stars.
  - A top bar: "Testarossa OS" in pink-magenta, "v0.1.0" in grey, and
    "up 00:00:0N" on the right. The uptime changes every second.
  - A narrow left rail with four squares: AR, ME, JO, SY.
  - Four hub cards in a 2x2 grid: Archive, Messages, Journal, System.
    The Archive card has a bright cyan outline (it has focus).
  - Three status cards on the right: UPTIME, MEMORY, HEAP. The numbers change.
  - A bottom bar: "Tab / arrows move   Enter open   Esc close", and two
    buttons on the right: "About (A)" and "Terminal (T)".
  - A small white arrow pointer in the middle of the screen.


=====================================================================
PART B - DESKTOP CHECKS
=====================================================================

Click the QEMU window first so it has keyboard focus.

TEST 4 - FOCUS MOVES WITH ARROWS
--------------------------------
Press Right. EXPECTED: the cyan outline moves to Messages (top right tile).
Press Down.  EXPECTED: the outline moves to System (bottom right tile).
Press Left.  EXPECTED: the outline moves to Journal (bottom left tile).
Press Left again. EXPECTED: it stays on Journal (no wrap, no crash).
Press Up. EXPECTED: the outline moves to Archive.


TEST 5 - FOCUS MOVES WITH TAB
-----------------------------
Press Tab four times, one at a time.
EXPECTED: the outline goes Archive -> Messages -> Journal -> System -> Archive.
The rail square on the left next to the focused tile also lights up cyan.


TEST 6 - ARCHIVE LIST
---------------------
Move focus to Archive, press Enter.
EXPECTED: a panel titled "Archive" opens in the middle. It lists:
    /readme.txt
    /archive/entry01.txt
    /system/about.txt
The first row is highlighted. A hint line says "Up/Down choose   Enter open".


TEST 7 - READ A FILE
--------------------
In the Archive panel, press Down once, then Enter.
EXPECTED: the panel title becomes "Archive - file" and shows:
    ENTRY 01
    The machine was left running in a back room.
    The screen still shows the last thing someone typed.
    Nobody has come back to turn it off.
and a hint "Esc back to the list" at the bottom.


TEST 8 - ESC BEHAVES IN TWO STEPS
---------------------------------
Press Esc. EXPECTED: back to the file list (title "Archive").
Press Esc again. EXPECTED: the panel closes. The desktop is visible again.
Press Esc once more with no panel open. EXPECTED: nothing happens.


TEST 9 - SYSTEM MONITOR IS LIVE
-------------------------------
Move focus to System (Tab until it is outlined), press Enter.
EXPECTED: a "System Monitor" panel with these lines:
    uptime        NN s
    timer ticks   NNNN at 100 Hz
    usable RAM    NNNNNN KiB
    free frames   NNNNNN KiB
    heap free     NNN KiB
    heap size     512 KiB
The uptime and ticks increase while the panel is open. Watch for 10 seconds.
The ticks number is about 100 times the uptime seconds.
Press Esc to close.


TEST 10 - JOURNAL AND MESSAGES
------------------------------
Focus Journal, press Enter.
EXPECTED: a panel with "built-in demo entry, copied from the archive" and the
same four lines as entry01. Press Esc.

Focus Messages, press Enter.
EXPECTED: "No messages." and "Messaging is not built yet." Press Esc.
This is the honest placeholder. It must not show fake messages.


TEST 11 - ABOUT PANEL
---------------------
On the desktop with no panel open, press  a  (the letter A).
EXPECTED: a panel "About Testarossa" opens. It shows the name and version,
a one-line description, then five lines: CPU, Kernel, Memory, Display,
and Paging. A final grey line says everything on screen is drawn by the
kernel. Press Esc to close.


=====================================================================
PART B2 - TERMINAL, WINDOWS, MOUSE
=====================================================================

Use the normal build (make run). QEMU takes the mouse when you click its
window. Press Ctrl+Alt+G to get your mouse back.

TEST 25 - TERMINAL WINDOW
-------------------------
On the desktop press  t.
EXPECTED: a "Terminal" window with "Shell ready. Type help." and a cyan
"testarossa>" prompt, with an underline cursor after it.
Type  help  Enter, then  ls  Enter, then  cat /readme.txt  Enter.
EXPECTED: the same output as in Tests 14 and 16. The line "Nothing here is
written to disk, so it resets on every boot." wraps onto a second line.
Type  clear  Enter. EXPECTED: the window empties, prompt at the top.
Type  a  and  t. EXPECTED: they appear as letters in the Terminal; no window opens.

TEST 26 - SEVERAL WINDOWS
-------------------------
With the Terminal open, press Esc. Then press Enter on Archive, then  a.
EXPECTED: two windows, Archive below and About on top, About a little lower
and to the right. Only the top window has a cyan border.
Press Tab. EXPECTED: Archive comes to the top. Press Tab again: About again.
Press  t. EXPECTED: Terminal opens on top of both (three windows).
Press Esc three times. EXPECTED: the windows close one at a time, top first.

TEST 27 - THE TERMINAL KEEPS ITS TEXT
-------------------------------------
Open the Terminal, type  echo still here  Enter, press Esc, then  t  again.
EXPECTED: "still here" is still in the window. The shell does not restart.

TEST 28 - MOUSE ON THE DESKTOP
------------------------------
Move the mouse. EXPECTED: the pointer follows and stops at the screen edges.
Click the System tile. EXPECTED: System Monitor opens.
Click the pink x on its title bar. EXPECTED: it closes.
Click the rail square JO. EXPECTED: Journal opens. Close it.
Click "Terminal (T)" in the dock. EXPECTED: the Terminal opens.

TEST 29 - MOUSE WITH WINDOWS
----------------------------
Open Archive (click the tile). Click /system/about.txt once.
EXPECTED: that row is selected. Click it again. EXPECTED: the file opens.
Click "About (A)" in the dock. EXPECTED: About opens on top of Archive.
Click a visible part of the Archive window. EXPECTED: Archive comes to the top.
Click the empty desktop. EXPECTED: nothing happens.


=====================================================================
PART C - TEXT SHELL CHECKS
=====================================================================

The text shell runs in a build without graphics. Close the QEMU window, then:

    make clean
    make run-text

A text QEMU window opens with the shell.
Afterwards, to get the desktop back, run:  make clean && make

TEST 12 - TEXT SHELL STARTS
---------------------------
EXPECTED: the top of the window shows the banner and "Shell ready. Type help."
and a prompt "testarossa>". The prompt word is cyan, the banner is magenta,
the body text is grey.

TEST 13 - TYPING, SHIFT, BACKSPACE
----------------------------------
Type  hi  and Enter.                       EXPECTED: "hi" appears, new prompt.
Type  Hello World 123 !?  and Enter.       EXPECTED: exactly as typed.
Type  abc  then Backspace once.            EXPECTED: "c" disappears.
Press Backspace many times.                EXPECTED: stops at the prompt.

TEST 14 - HELP, ABOUT, VERSION, ECHO
------------------------------------
help     EXPECTED: "Commands:" and the list (help, about, version, clear,
         echo, uptime, mem, ls, cat).
about    EXPECTED: "Testarossa OS 0.1.0" and seven indented lines.
version  EXPECTED: exactly  Testarossa OS 0.1.0
echo hello there  EXPECTED: "hello there".
echo      EXPECTED: an empty line, no error.

TEST 15 - UPTIME AND MEM
------------------------
uptime   EXPECTED: "up N s (T ticks at 100 Hz)". Wait 10 s and type it again.
         The second N is about 10 bigger.
mem      EXPECTED: four lines: usable, free, in use (KiB), and heap (KiB free of 512 KiB).

TEST 16 - ARCHIVE FROM THE SHELL
--------------------------------
ls                    EXPECTED: three paths and "3 files".
cat /readme.txt       EXPECTED: four lines beginning "Testarossa OS keeps".
cat /archive/entry01.txt   EXPECTED: "ENTRY 01" and three lines.
cat /system/about.txt      EXPECTED: "TESTAROSSA OS 0.1.0" and two lines.

TEST 17 - ERRORS ARE MAGENTA
----------------------------
cat /nope.txt    EXPECTED: magenta "cat: no such file: /nope.txt"
cat              EXPECTED: magenta "cat: usage: cat <path>"
bogus            EXPECTED: magenta "unknown command: bogus  (type help)"

TEST 18 - CLEAR
---------------
clear            EXPECTED: the screen empties, prompt at the top.

TEST 19 - LONG INPUT
--------------------
Hold the letter  x  until about 150 characters are typed, then Enter.
EXPECTED: no crash. The line is cut at about 127 characters.
Then type  version  and Enter. EXPECTED: it still works.


=====================================================================
PART D - KERNEL SELF-TESTS IN THE LOG
=====================================================================

These run on every boot, before the desktop or shell starts. They are
checked by reading the boot log (Test 2). Repeat the boot three times.

TEST 20 - PMM AND PAGING: same result every boot
  EXPECTED: "PMM self-test: PASS", "paging self-test: PASS" on all three boots.

TEST 21 - HEAP: same result every boot
  EXPECTED: "heap self-test: PASS" on all three boots.

TEST 22 - FREE MEMORY IS STABLE
  EXPECTED: the "PMM: memory map read, NNNNNN KiB free" number is the same
  on all three boots (the same QEMU memory size).


=====================================================================
PART E - CRASH TESTS
=====================================================================

These build special kernels that crash on purpose. Check that the kernel
reports the crash and stops. Afterwards go back to the normal kernel.

TEST 23 - DIVIDE BY ZERO
------------------------
    make clean
    make fault-test
    make run

EXPECTED: after "PIT programmed to 100 Hz" a line like

    !! EXCEPTION divide error vector=0x00000000 err=0x00000000 eip=0x...
    system halted

TEST 24 - PAGE FAULT
--------------------
    make clean
    make pf-test
    make run

EXPECTED:

    !! EXCEPTION page fault vector=0x0000000E err=0x00000000 eip=0x...
       address=0x80000000 page not present, read, kernel mode
    system halted

Then go back to normal:

    make clean
    make
    make run

EXPECTED: the desktop starts again.


=====================================================================
PART F - DEBUG CHALLENGES
=====================================================================

For each challenge, say what you did, what happened, and whether it is a
bug. Do not fix the code for these. Report what you find. Some of them are
known problems. Confirm them and say exactly how to reproduce them.

D1 - BACKSPACE ACROSS A WRAP  (known bug, text shell: make run-text)
    Type 100 letters in one line (it wraps past column 80). Press Backspace
    50 times, then type  z.
    EXPECTED: 50 letters remain, then  z.
    Note what actually appears and where the z lands.
    Try the same in the desktop Terminal window (it wraps at 56 columns).

D2 - LONG LINES IN A DESKTOP PANEL  (suspected: clipping)
    The panels do not wrap text. Read a file in the Archive, or find a long
    line. Does any text run past the right edge of the panel? Does it run
    past the bottom of the panel, or over the hub cards?

D3 - ARCHIVE SELECTION LIMITS
    In the Archive list, press Up on the first row, then Down past the last row.
    EXPECTED: the selection stops at the first and last row. No crash, no blank row.

D4 - OPEN AND CLOSE QUICKLY
    Open a panel and close it with Esc, 30 times quickly (about 5 per second).
    EXPECTED: no freeze, no leftover pixels from the closed panel.

D5 - ESC WITH NOTHING OPEN
    Press Esc 20 times on the desktop with no panel open.
    EXPECTED: nothing happens. The focus does not move.

D6 - CAPS LOCK  (known limitation)
    Press Caps Lock, then type  abc  on the desktop or in the shell.
    Expected for now: lowercase letters (Caps Lock is not handled). Write
    down what you see.

D7 - LONG RUN
    Leave the desktop running for 10 minutes. Note the top-bar uptime at
    the start and at the end. Check the Memory and Heap cards do not change
    much (nothing should leak). Check the keyboard still responds.


=====================================================================
HOW TO REPORT
=====================================================================

For each test or challenge, write one line:

    Test N: PASS  or  FAIL        (or  D1: found / not found)
    If FAIL or found: what you pressed, what you expected, what you saw.
    If possible: a screenshot (Windows: Win+Shift+S, then paste into your report).

Send the list to the project owner, or open a GitHub issue with the label
testing. Use bug for real failures.

Thank you for testing!
