TESTAROSSA OS - TEST GUIDE FOR CLASSMATES
==========================================

You do not need to know the code to do this. Follow the steps in order.
Each test has an EXPECTED result. If what you see differs, write it down
(see "How to report" at the bottom).

Time needed: about 20-30 minutes.


0. WHAT YOU NEED
----------------
- Windows 10 or 11 with WSL2 and Ubuntu installed.
  (Open PowerShell and run:  wsl --install -d Ubuntu  if you do not have it.)
- A copy of the project (git clone or the folder you were given).


1. ONE-TIME SETUP (inside Ubuntu / WSL)
---------------------------------------
Open the "Ubuntu" app, go to the project folder, and install the tools:

    sudo apt update
    sudo apt install -y nasm qemu-system-x86 make gcc

Go to the project. Windows drives appear under /mnt, for example:

    cd /mnt/c/path/to/Operating_System

Check the tools exist (each should print a path):

    which nasm qemu-system-i386 make gcc


2. TEST 1 - BUILD FROM CLEAN
----------------------------
    make clean
    make

EXPECTED:
  - Lines like "nasm -f elf32 ..." and "gcc -m32 ..." appear.
  - A line "ld -m elf_i386 ..." appears.
  - The command ends with no "error:" lines.
  - The file build/testarossa.elf exists:  ls -l build/testarossa.elf

(A warning about "RWX permissions" from ld is known and OK.)


3. TEST 2 - BOOT AND SERIAL LOG
-------------------------------
    make run

A QEMU window opens. The terminal should also print these lines, in order:

    Testarossa OS v0.1.0 booting...
    GDT loaded
    IDT loaded
    PIC remapped to vectors 32-47; IRQ0 (timer) and IRQ1 (keyboard) unmasked
    PIT programmed to 100 Hz
    Shell ready. Type help.
    testarossa>

EXPECTED: all six lines appear, and the prompt "testarossa> " is at the end.

Close the QEMU window when you are done. The terminal returns to the prompt.


4. TEST 3 - VGA SCREEN
----------------------
Run  make run  again. Look at the QEMU window.

EXPECTED:
  - Pink/magenta text on a black background.
  - The top line shows "~*~ Testarossa OS ~*~  v0.1.0".
  - The prompt "testarossa> " is visible with a blinking cursor after it.
    (The cursor must be at the end of the prompt, not somewhere else on
    the screen.)


5. TEST 4 - TYPING
------------------
Click the QEMU window so it has keyboard focus. Type:

    hi

EXPECTED: "hi" appears after the prompt, one letter at a time.
Then press Enter. The shell prints a new prompt on the next line.


6. TEST 5 - SHIFT KEY
---------------------
Type (holding Shift for the capital letters):

    Hello World 123 !?

EXPECTED: the line appears exactly as typed:

    testarossa> Hello World 123 !?

H and W are capitals. The "!" is Shift+1 and the "?" is Shift+/.

Note: this shell is US keyboard layout only.


7. TEST 6 - BACKSPACE
---------------------
Type  abc  then press Backspace once.
EXPECTED: the "c" disappears and the cursor moves back one place.
Press Backspace several more times past the prompt.
EXPECTED: it stops at the prompt. It does not erase "testarossa> ".


8. TEST 7 - HELP
----------------
Type  help  and press Enter.

EXPECTED: a list that begins "Commands:" and includes:
  help, about, version, clear, echo
and a line "Not built yet: mem, ls, cat".


9. TEST 8 - ABOUT AND VERSION
-----------------------------
Type  about  and press Enter.
EXPECTED: "Testarossa OS 0.1.0" and five lines describing the system
(32-bit protected mode, VGA text, serial COM1, PS/2 keyboard).

Type  version  and press Enter.
EXPECTED: exactly  Testarossa OS 0.1.0


10. TEST 9 - ECHO
-----------------
Type  echo hello there  and press Enter.
EXPECTED: the line  hello there  is printed under the command.

Type  echo  (with nothing after it) and press Enter.
EXPECTED: an empty line is printed. No error.


11. TEST 10 - UPTIME (TIMER)
----------------------------
Type  uptime  and press Enter. Write down the number after "up".
Wait about 10 seconds. Type  uptime  again.

EXPECTED: the first number is small, for example 3. The second number is
about 10 bigger. The ticks value is about 100 times the seconds value.
Example:  up 13 s (1302 ticks at 100 Hz)


12. TEST 11 - NOT-YET COMMANDS
------------------------------
Type each of these, pressing Enter after each:

    mem
    ls
    cat

EXPECTED: each prints  "<name>: not implemented yet (needs ...)".
The system must NOT crash, and must NOT pretend to show data.


13. TEST 12 - UNKNOWN COMMAND
-----------------------------
Type  bogus  and press Enter.
EXPECTED: "unknown command: bogus  (type help)" and a new prompt.


14. TEST 13 - CLEAR
-------------------
Type  clear  and press Enter.
EXPECTED: the screen empties. The prompt "testarossa> " appears at the top.
Old text is gone.


15. TEST 14 - LONG INPUT
------------------------
Hold down the letter  x  until about 150 characters are typed on one line,
then press Enter.

EXPECTED: no crash, no freeze. The line is cut at about 127 characters.
The shell still answers the next command (type  version  and Enter).


16. TEST 15 - STRESS
--------------------
Type quickly for 20 seconds: a mix of letters, Enter and Backspace.
EXPECTED: the screen keeps updating and the keyboard keeps responding.
The system must not freeze.


17. TEST 16 - REPEATED BOOT
---------------------------
Close QEMU. Run  make run  three times in a row.
EXPECTED: each boot prints the same six startup lines. Nothing changes
between runs.


18. TEST 17 - EXCEPTION PATH (THE KERNEL CATCHES A CRASH)
---------------------------------------------------------
This builds a special copy of the kernel that divides by zero on purpose.

    make clean
    make fault-test
    make run

EXPECTED: after the usual startup lines, you see a line like

    !! EXCEPTION divide error vector=0x00000000 err=0x00000000 eip=0x...
    system halted

The machine stops there. This is correct.

Then go back to the normal kernel:

    make clean
    make

Run  make run  once more to check that the normal shell works again.


HOW TO REPORT
-------------
For each test, write one line:

    Test N: PASS  or  FAIL
    If FAIL: what you typed, what you expected, what you saw.
    If possible: the last 10 lines of terminal output (copy and paste).

Send the list to the project owner, or add it as a GitHub issue with the
label  testing  (and  needs-test  if a feature is still unverified).

Thank you for testing!
